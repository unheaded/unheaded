#   How do I parse a string to an integer in Rust?

Parsing a string to an integer in Rust is a very common task, and the idiomatic way to do it is by using the methods provided by the `str` type and the `Result` type, specifically the `parse()` method.

Here is a comprehensive guide covering the standard approach, error handling, and common variations.

---

## 1. The Standard Approach: Using `str::parse()`

The `parse()` method is the most straightforward way. It attempts to convert the string slice (`&str`) into the desired type (in this case, `i32`, `u64`, etc.).

**Key Feature:** `parse()` returns a `Result<T, E>`, where `T` is the target type (e.g., `i32`) and `E` is an error type (e.g., `ParseIntError`). This forces you to handle the case where the string is invalid.

### Example 1: Basic Parsing

```rust
fn main() {
    let s1 = "12345";
    let s2 = "hello";

    // Attempt to parse s1 into an i32
    let num1: Result<i32, std::num::ParseIntError> = s1.parse();

    match num1 {
        Ok(number) => println!("Successfully parsed '{}' into i32: {}", s1, number),
        Err(e) => println!("Error parsing '{}': {}", s1, e),
    }

    // Attempt to parse s2 into an i32
    let num2: Result<i32, std::num::ParseIntError> = s2.parse();

    match num2 {
        Ok(number) => println!("Successfully parsed '{}' into i32: {}", s2, number),
        Err(e) => println!("Error parsing '{}': {}", s2, e),
    }
}
```

**Output:**

```
Successfully parsed '12345' into i32: 12345
Error parsing 'hello': invalid digit found in string
```

## 2. Handling Errors with `match` (Explicit)

As shown above, using a `match` statement is the clearest way to handle the `Result`.

```rust
fn parse_with_match(s: &str) {
    match s.parse::<i32>() {
        Ok(num) => println!("Parsed successfully: {}", num),
        Err(e) => eprintln!("Failed to parse '{}': {}", s, e),
    }
}

fn main() {
    parse_with_match("42");
    parse_with_match("not_a_number");
}
```

---

## 3. Handling Errors with `unwrap()` or `expect()` (Caution!)

If you are absolutely certain that the input string will always be valid (e.g., it comes from a trusted internal source or a fixed format), you can use `unwrap()` or `expect()`.

**⚠️ Warning:** Using `unwrap()` or `expect()` will cause your program to **panic** (crash) if the parsing fails. Use these only when failure is truly an unrecoverable error in your application logic.

```rust
fn main() {
    let s = "99";

    // Using unwrap() - panics on error
    let number = s.parse::<i32>().unwrap();
    println!("The number is: {}", number);

    // Using expect() - panics with a custom message on error
    let number_expect = s.parse::<i32>().expect("Failed to parse the input string");
    println!("The number is: {}", number_expect);
}
```

---

## 4. Using `unwrap_or()` or `unwrap_or_else()` (Providing a Default)

If you want to provide a default value instead of panicking on failure, you can use methods on the `Result`.

### Example 4: Providing a Default Value

```rust
fn main() {
    let s1 = "100";
    let s2 = "invalid";

    // If parsing succeeds, use the number; otherwise, use 0.
    let num1 = s1.parse::<i32>().unwrap_or(0);
    println!("Parsed num1: {}", num1); // Output: 100

    let num2 = s2.parse::<i32>().unwrap_or(0);
    println!("Parsed num2: {}", num2); // Output: 0
}
```

## 5. Parsing to Different Integer Types

The process is identical, you just change the target type in the generic signature (`::<T>`).

```rust
fn main() {
    let s = "5000000000"; // Too large for i32

    // Parsing to u64 (unsigned 64-bit integer)
    match s.parse::<u64>() {
        Ok(num) => println!("Parsed as u64: {}", num),
        Err(e) => eprintln!("Error parsing as u64: {}", e),
    }

    // Parsing to i64 (signed 64-bit integer)
    match s.parse::<i64>() {
        Ok(num) => println!("Parsed as i64: {}", num),
        Err(e) => eprintln!("Error parsing as i64: {}", e),
    }
}
```
