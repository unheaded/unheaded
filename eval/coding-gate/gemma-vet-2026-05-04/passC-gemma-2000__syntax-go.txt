## Method 1: Using Exceptions (The Standard Approach)

**When to use it:** This is the preferred method for handling **unexpected, runtime errors** (e.g., file not found, network connection failed, division by zero, invalid input format). Exceptions allow the program to "break out" of the normal flow and jump to a specific error-handling block.

### 💡 How it works:

You wrap the function call in a `try` block. If the function throws an error (raises an exception), the code inside the `except` (or `catch`) block is executed instead of crashing the program.

### 💻 Examples:

#### Python (using `try...except`)

```python
def divide(a, b):
    try:
        result = a / b
        return result
    except ZeroDivisionError:
        # Handle the specific error
        print("Error: Cannot divide by zero.")
        return None  # Return a safe value or raise a custom error

# --- Calling the function ---
result1 = divide(10, 2)
print(f"Result 1: {result1}")  # Output: Result 1: 5.0

result2 = divide(10, 0)
print(f"Result 2: {result2}")  # Output: Error: Cannot divide by zero.
```

#### Java / C# (using `try...catch`)

```java
public class ErrorChecker {
    public static int divide(int a, int b) {
        try {
            int result = a / b;
            return result;
        } catch (ArithmeticException e) {
            // Handle the specific error
            System.err.println("Error: Cannot divide by zero.");
            return -1; // Return an error code
        }
    }

    public static void main(String[] args) {
        int result1 = divide(10, 2);
        System.out.println("Result 1: " + result1);

        int result2 = divide(10, 0);
        System.out.println("Result 2: " + result2); // Output: -1
    }
}
```

## Method 2: Checking Return Codes or Status Values

**When to use it:** This method is used when the function is designed to signal success or failure explicitly, rather than throwing an exception. This is common in low-level programming, network APIs, or database operations.

### 💡 How it works:

The function returns two things: the actual data (if successful) and a separate status indicator (like a boolean, an integer code, or an enum). You check the status code immediately after the call.

### 💻 Example (Conceptual)

```python
def read_file(filename):
    """Returns a tuple: (data, status_code)"""
    try:
        with open(filename, 'r') as f:
            data = f.read()
            return data, 200  # 200 means success
    except FileNotFoundError:
        return None, 404  # 404 means file not found

# --- Calling the function ---
file_data, status = read_file("non_existent_file.txt")

if status == 200:
    print("File read successfully:", file_data)
else:
    print(f"Operation failed with status code: {status}")
```

## Method 3: Checking for Null or Optional Values

**When to use it:** This is used when the function might legitimately return "nothing" (i.e., `null`, `None`, or an empty object) without it being an error. This is common in languages like Swift, Kotlin, and TypeScript.

### 💡 How it works:

You check if the returned value is `null` or `None` before attempting to use it.

### 💻 Example (Conceptual - JavaScript/TypeScript)

```javascript
function findUser(id) {
    if (id === 1) {
        return { name: "Alice", age: 30 };
    }
    // If user is not found, return null
    return null;
}

// --- Calling the function ---
const user = findUser(99);

if (user === null) {
    console.log("Error: User not found.");
} else {
    console.log("User found:", user.name);
}
```
