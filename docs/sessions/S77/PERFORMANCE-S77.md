## Purpose

This document establishes the performance baseline for Unheaded's S77 infrastructure. It defines the test methodology, expected ranges for each metric, and provides a template for recording results across deployments.

---

## Test Methodology

### Tools

- **`cmd/perf-benchmark`** — Go benchmarking harness (primary)
- **`scripts/wireguard/verify-wireguard.sh`** — WireGuard-specific verification
- **Standard tools:** `ping`, `ping6`, `curl`, `tcpdump`, `iperf3`

### Environment

| Parameter | Value |
|-----------|-------|
| WEST | 192.168.13.2 (test cluster) |
| EAST | 192.168.13.1 (4-core, 8GB DDR3, staging) |
| P2P Link | Direct Ethernet, 192.168.13.0/24 |
| WireGuard | fd00:dead:beef::/48, port 51820 |
| OS | Linux 6.x |
| Go | 1.25+ |

### Conditions

- Tests should be run with minimal background load
- Run at least 50 iterations per test (default in perf-benchmark)
- Discard first 3-5 iterations as warmup
- Record min/avg/median/p95/p99 for each metric
- Run tests from WEST unless otherwise noted

## How to Run Benchmarks

### Quick Run (All Tests)

```bash
cd ~/tmp/unheaded
go run ./cmd/perf-benchmark
```

### Custom Configuration

```bash
# More iterations, custom output
go run ./cmd/perf-benchmark \
  -iterations 100 \
  -output results/bench-$(date +%Y%m%d).json

# Test against different endpoints
go run ./cmd/perf-benchmark \
  -east-p2p 192.168.13.1 \
  -east-wg fd00:dead:beef::1 \
  -health http://localhost:19000/health \
  -wotan http://localhost:18000
```

### WireGuard-Specific Verification

```bash
./scripts/wireguard/verify-wireguard.sh
```

### Manual Latency Checks

```bash
# P2P baseline
ping -c 50 192.168.13.1

# WireGuard overlay
ping6 -c 50 fd00:dead:beef::1

# HTTP health
for i in $(seq 1 50); do
  curl -o /dev/null -s -w '%{time_total}\n' http://localhost:19000/health
done

# Throughput (requires iperf3 on both hosts)
# EAST: iperf3 -s -B fd00:dead:beef::1
# WEST: iperf3 -c fd00:dead:beef::1 -V -t 30
```

## Interpreting Results

### Red Flags

- **P2P RTT > 1ms:** Check for interface errors (`ip -s link show enp*`), CPU throttling
- **WG overhead > 1ms:** Check CPU load during test, consider MTU tuning
- **HTTP health > 10ms:** Service may be under load or GC-ing; check with `pprof`
- **High P99 vs P95:** Indicates tail latency — look for GC pauses, context switches
- **Packet loss > 0%:** Indicates buffer overflow or interface issues

### Optimization Levers

1. **MTU tuning:** Increase P2P MTU to 9000 (jumbo frames) if NIC supports it
2. **CPU pinning:** Pin WireGuard to dedicated core with `taskset`
3. **IRQ affinity:** Bind NIC interrupts to specific cores
4. **TCP tuning:** Increase buffer sizes for throughput tests
5. **Go GC tuning:** Set `GOGC=200` for services under benchmark
