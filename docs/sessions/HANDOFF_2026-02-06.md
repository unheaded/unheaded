## Bug Fixes Applied This Session

### 1. pkg/wotan-client: Double-Close Channel Panic (PRODUCTION FIX)

**File:** `pkg/wotan-client/client.go`
**Issue:** `Client.Close()` iterated `c.channels` and closed channels that `pollMessages()` had already closed via `defer close(ch)`, causing a panic.
**Fix:** Added `sync.Once` wrapping for channel close operations to make `Close()` idempotent.

### 2. services/gauntlets: Test Expectation Mismatch

**File:** `services/gauntlets/gauntlets_test.go`
**Issue:** Tests expected 3 builtin commands but service now registers 6 (health, health-standard, ready, metrics, version, commands).
**Fix:** Updated test expectations from 3→6 builtins and 5→8 total (after custom registrations).

### 3. services/cloak: Pointer Aliasing Bug in Test

**File:** `services/cloak/cloak_test.go`
**Issue:** `TestSessionLifecycle` compared `got.LastActivity.After(sess.LastActivity)` but both `got` and `sess` pointed to the same `Session` struct in memory. After `TouchSession()`, both had the updated time.
**Fix:** Saved `originalActivity := sess.LastActivity` before mutation, then compared against that.

### Key Diff: wotan-client Production Fix

```go
// NEW: safeChannel wraps a channel with sync.Once for idempotent close
type safeChannel struct {
    ch   chan *Message
    once sync.Once
}

func (sc *safeChannel) closeCh() {
    sc.once.Do(func() { close(sc.ch) })
}

// Client.channels changed from map[string]chan *Message
//                           to map[string]*safeChannel

// pollMessages now calls sc.closeCh() instead of close(ch)
// and removes from c.channels map on exit

// Client.Close() now calls sc.closeCh() instead of close(ch)
// — safe even if pollMessages already closed the channel
```
