# S77 — Phase 2: WireGuard IPv6 Overlay Design

**Sprint:** S77 (Age 2 Acceleration)
**Phase:** 2 — IPv6 Overlay
**Status:** Shipped (setup + verify scripts in-tree; bare-metal validation on WEST/EAST). Corrected 2026-10-23 (S-QUANTUM-ARMOR): PSK state, post-quantum section, references.
**Subnet:** `fd00:dead:beef::/48` (ULA, RFC 4193)

---

## Why

Cross-host BPF flow graph (WEST ↔ EAST) needs a private encrypted overlay that:

1. Survives NAT and arbitrary intermediate networks (point-to-point or via internet).
2. Provides cryptographic identity per host (static Curve25519 keypair per host).
3. Stays out of the public IPv4 space (avoids ISP filtering, future-proof for v6-only fabric).
4. Carries Monad protocol packets without per-flow tunneling overhead.

WireGuard delivers on all four. The Kingdom uses ChaCha20-Poly1305 AEAD (built-in, not configurable) over UDP/51820 inside a single ULA `/48`.

## Crypto

- **Handshake:** Noise_IKpsk2. **Curve:** Curve25519.
- **Symmetric:** ChaCha20-Poly1305 AEAD.
- **Hash/MAC:** BLAKE2s.
- **PSK:** ON. One static 256-bit preshared key, generated by `setup-wireguard.sh` (`wg genpsk`) and set on both peers (`PresharedKey =` in each host's `wg0.conf`). Both hosts report it set (2026-10-23); it has not been rotated since setup (2026-03-25).
- **Rekey interval:** WireGuard defaults (new handshake after 120 s of session age; session keys rejected after 180 s).

## Post-quantum

WireGuard's key agreement is Curve25519 only. Someone who records the tunnel today and later breaks Curve25519 with a quantum computer recovers the session keys, unless the PSK is mixed in: every handshake hashes the PSK into the key schedule, so recorded traffic stays confidential as long as the PSK stays secret (ADR-105, Proposed).

- **Rotation:** `scripts/wireguard/rotate-psk.sh` (dry run by default; `--apply` rotates). It runs on west, generates a fresh PSK, sends it to east over SSH only when that session negotiated a hybrid post-quantum KEX (`mlkem768x25519-sha256` or `sntrup761x25519-sha512`), sets it on east then west with `wg set ... preshared-key <file>`, waits for a new handshake and rolls both hosts back to the previous PSK if none comes. On success it rewrites `PresharedKey` in `wg0.conf` and keeps the key in `/etc/wireguard/wg0.psk` (0600; its mtime is the last rotation). The PSK never appears on a command line or in a log. Tested against stubs by `scripts/wireguard/test-rotate-psk.sh` (registered in the meta-gate).
- **Timer:** `deploy/systemd/unheaded-wg-psk-rotate.{service,timer}` (weekly), shipped but not enabled. The first live rotation and enabling the timer are ESCALATE E3: `docs/security/pq-host-escalations.md`.
- **Rosenpass** (a post-quantum key exchange that feeds WireGuard's PSK) is parked: it brings a C/liboqs dependency (ADR-004).

## Setup + verify scripts

- `scripts/wireguard/setup-wireguard.sh` — generates both keypairs and the PSK on WEST, writes `/etc/wireguard/wg0.conf` on each host, enables `wg-quick@wg0`. `ListenPort = 51820`, `Endpoint =` per peer, `PersistentKeepalive = 25`.
- `scripts/wireguard/verify-wireguard.sh` — checks `wg0` exists on both hosts, pings each peer's overlay address, and reads `wg show` for a recent handshake and nonzero transfer. Prints PASS/FAIL/WARN lines.

## Cross-host BPF flow graph

The flow-tracker BPF program emits Monad packets carrying `(src_ipv6, dst_ipv6, flow_label, latency_µs)` tuples. Userspace ingestion in `cmd/trace-collector` decodes them and republishes to wotan topic `flow.cross_host`. WireGuard ULA addresses are recognized as kingdom-internal and labeled as such in the trace UI.

## Security considerations

- Peer public keys live only in each host's `/etc/wireguard/wg0.conf` (root, 0600). There is no signed peer registry.
- WireGuard does NOT replace pkg/auth; HTTP/gRPC traffic over the overlay still passes through APIKey or JWT authenticators.
- The overlay is `fd00:dead:beef::/48` (private). Kingdom publishing surface remains ipv4 + global ipv6 via the gateway service.
