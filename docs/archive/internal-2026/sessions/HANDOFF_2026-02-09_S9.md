## What Was Done

### P0: Topic Pub/Sub HTTP Endpoints (Root Cause of 404s)

**Problem:** `wotan-client` expected `/api/v1/topics/{topic}/subscribe|publish|messages` but Wotan only had room-based chat endpoints. Every service trying to subscribe got 404.

**Fix:** Created `services/wotan/internal/api/topics.go` (~388 lines):

| Handler | Route | Method | What It Does |
|---------|-------|--------|-------------|
| SubscribeTopic | `/api/v1/topics/{topic}/subscribe` | POST | Auto-creates room, auto-approves member, returns subscriber info |
| PublishTopic | `/api/v1/topics/{topic}/publish` | POST | Publishes payload with atomic monotonic sequence numbers |
| GetTopicMessages | `/api/v1/topics/{topic}/messages` | GET | Returns messages with `after_seq` and `limit` query params |
| ListTopics | `/api/v1/topics` | GET | Lists all active topics |
| TopicRouter | `/api/v1/topics/` | * | URL dispatcher |

Key design: Topics map to Rooms internally. `extractTopic()` validates topic names (alphanumeric, dots, hyphens, underscores). Auto-approval bypasses the admin gate for topic subscribers.

**Files:**
- `services/wotan/internal/api/topics.go` — NEW
- `services/wotan/cmd/wotan/main.go` — Added `InitTopics()` + route registration
- `services/wotan/internal/api/handlers.go` — Added `topicSeqs`/`topicSubs` to Server struct

### P2: Fix 6 Data Races

| # | Package | Test | Root Cause | Fix |
|---|---------|------|-----------|-----|
| 1 | `pkg/alerting` | TestWotanChannel | Test reads `mockPublisher.Events` without lock | Added `EventCount()` and `BatchCount()` thread-safe accessors to `MockWotanPublisher` |
| 2 | `pkg/alerting/notify` | TestWotanChannel_PublishWithRetryExhausted | FlushLoop drains queue before second Send (timing-dependent) | Rewrote with `blockingBatchPublisher` that freezes flushLoop deterministically |
| 3 | `pkg/deploy/pipeline` | TestHealthGateSetEventCallback | Callback goroutine writes shared var, test reads after Sleep | Replaced bare `receivedEvent` with channel synchronization |
| 4 | `pkg/deploy/pipeline` | TestSetEventCallback | Same pattern as #3 | Same fix — channel with `select`/timeout |
| 5 | `pkg/deploy/pipeline` | TestInitiateRollback | `executeRollback` goroutine writes `rollback.State` under `m.mu`, test reads without lock | Read `rollback.State` under `manager.mu.RLock()`, accept Pending or Executing |
| 6 | `pkg/dns` | TestEnhancedHealthChecker_CheckNow + DegradedState | `ep.Health` written under `hc.mu` in checkEndpoint, read under `sd.mu` in UpdateEndpointHealth — shared pointer, different locks | Added `health`/`responseTime` local copies to `endpointHealthState`, all reads in health checker use local copies under `hc.mu`, writes to shared `ep` go exclusively through `UpdateEndpointHealth` under `sd.mu` |

**Race #6 detail:** The `*ServiceEndpoint` pointer is shared between `EnhancedHealthChecker` (uses `hc.mu`) and `EnhancedServiceDiscovery` (uses `sd.mu`). We added `health` and `responseTime` fields to `endpointHealthState` as local copies protected by `hc.mu`. Removed all direct reads of `epState.endpoint.Health` and `epState.endpoint.ResponseTime` from the health checker. Also removed `epState.endpoint.SuccessCount`/`FailCount` writes from `determineHealth()` since they were also shared-pointer mutations. `UpdateEndpointHealth` on the SD side is now the exclusive writer of `ep.Health`.

**Status:** Races 1-5 confirmed fixed (passed `-race`). Race 6 was deepened late in session (second race surfaced in `GetEndpointHealth` and `HealthStats` reading `ep.Health`/`ep.ResponseTime`). The deeper fix was applied but **needs re-verification:**
