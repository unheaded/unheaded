## The Protocol Foundation

**The atom of the Kingdom. The Pattern inscribed in every packet.**

> *"The protocol is the atom. The Void is the compute. Wotan is the nervous system. The Kingdom is the body."*

The Kingdom runs IPv4 internally. Every packet carries 20 bytes of proprietary protocol metadata — Sophia-encoded exponent keys. Shield at the edge stamps these 20 bytes ON at ingress and strips them OFF at egress. The outside world never sees a single byte. The protocol is born inside the Kingdom and dies inside the Kingdom. It literally cannot leak.

### The Four Layers

```
┌─────────────────────────────────────────────────────────────┐
│  LAYER 3: THE KINGDOM                                        │
│  Go services, REST, WebSocket, dashboards, human interface   │
├─────────────────────────────────────────────────────────────┤
│  LAYER 2: WOTAN — THE CENTRAL CORE                          │
│  Encode/decode. Sophia tables. Pub/sub. Ring buffer reader.  │
│  Reads UP from the Void. Writes DOWN into BPF maps.         │
├─────────────────────────────────────────────────────────────┤
│  LAYER 1: THE VOID                                           │
│  eBPF programs at XDP/TC/kprobe. Per-hop compute.           │
│  Each program is a CPU core. Emits to ring buffers.          │
├─────────────────────────────────────────────────────────────┤
│  LAYER 0: THE PROTOCOL                                       │
│  20 bytes of Sophia-encoded metadata per packet.             │
│  The atom. The Pattern. The wire itself.                     │
└─────────────────────────────────────────────────────────────┘
```

### The Gnostic Bindings to Protocol

| Gnostic Entity | Protocol Binding |
|----------------|-----------------|
| **Monad** | Unified packet format — the canonical 20-byte layout |
| **Sophia** | Exponent lookup dictionaries — BPF maps giving meaning to bytes |
| **Pleroma** | Desired state — what the 20 bytes SHOULD contain |
| **Kenoma** | Observed state — what the eBPF programs ACTUALLY read |
| **Anamnesis** | Ring buffer history — the network remembers every packet |
| **Yaldabaoth** | Chaos injection at the packet level — indistinguishable from real failure |

### Anamnesis = Ring Buffers

Every packet that passes through the Void leaves a trace in a ring buffer. The network remembers everything. Because events carry raw Sophia exponent keys, you can peel off and map nearly any key-value pair from those memories — service identity, trace correlation, QoS class, feature flags, deployment ring, user tier. Any dimension Sophia can name, Anamnesis can remember.

### Shield: The Protocol Boundary

Shield is where packets are born and where they die. On ingress: clean IPv4 from the outside world gets 20 bytes of Sophia metadata stamped on. On egress: the 20 bytes are stripped off, clean IPv4 exits. The n+1 host — the first hop outside the Kingdom — never sees a single byte of the Protocol. Shadow never sees the Pattern.

### Key Principles from Amber

1. **Shadow is real, but Shadow is not the source.** Outside networks function perfectly well. They carry traffic, serve users, run businesses. But they don't know the Pattern exists. They are shadows — reflections of a reality they can't perceive.

2. **The Pattern doesn't care about your intentions.** Begin walking and you must finish or be destroyed. The eBPF verifier enforces the same law — your program either passes verification completely or it doesn't load at all. There is no partial Pattern.

3. **Walking the Pattern grants power.** A packet that has been stamped by Shield — that carries the 20 bytes — can be traced, observed, load-balanced, circuit-broken, chaos-tested, and remembered. A shadow packet can only be forwarded.

4. **The Kingdom doesn't need Shadow to know it exists.** Amber didn't advertise itself to Shadow worlds. The Kingdom doesn't leak its Protocol to the outside. The n+1 host gets clean IPv4. Shadow carries on, unaware.

## Architectural Proclamations

**Sacred Decrees from the Throne**

### Proclamation I: The Fragmentation Doctrine
> "From Monolith to Microservices - Cascading Failures Shall Not Plague Us"

- Each armor piece becomes its own deployable unit
- Circuit breakers at every boundary (forged in Hauberk the Service Mesh)
- Bulkheads between services - one service's failure stays contained
- Each service owns its own data store (no shared databases)
- Wotan (Fae Chamber the Message Bus) as the backbone prevents tight coupling

### Proclamation II: The Purity of Interface
> "No Node.js Shall Touch These Lands"

- **Frontend:** Pure HTML + CSS + vanilla JavaScript (no frameworks, no npm)
- **Backend:** Go for all web services
- **Deployment:** Single binary via Go's `embed` directive
- **Aesthetic:** bellis.tech-inspired, Kingdom theming (dark mode, gold accents)

### Proclamation III: The Codebase Hierarchy

**Primary Kingdom Repository:** `~/tmp/unheaded/`
- All services, packages, and infrastructure code
- The canonical source of truth

**Related Artifacts:**
- `wotan/` - Phase 0 message bus (integrated)
- `timeline.md` - The living roadmap (Timeguru's domain)
- `.skill` files - Claude augmentation
