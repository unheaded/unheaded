## Status: IN PROGRESS — 368 Claude QA pairs generated (2026-04-06). kingdom-v5 training step 13150/16304, loss 0.047. Scientist overfitting warning: epoch 1 checkpoint test required before epochs 2+3. CS sheets + learning library distillation queued (Wave 10 Phase 2 continuation).

## Context

Zhenai's LoRA fine-tuning (kingdom-v2.zlora) produced degenerate output despite
loss decreasing from 14.33 to 8.77. Root cause: the 3,965 QA training pairs were
auto-generated by Mistral-7B itself — the model teaching itself from documents
it barely understands. Garbage in, garbage out.

Claude (Haiku/Sonnet) actually understands code, architecture, and infrastructure.
Using Claude to generate training data is **distillation** — a stronger model
teaching a weaker one. This is established practice (Alpaca, Vicuna, WizardLM all
used GPT-generated training data).

## Decision

**Use Claude Haiku to generate 3-4K expert-quality QA pairs from 318 Kingdom documents,
then train kingdom-v4.zlora on the combined dataset (original + distilled).**

### Pipeline

```
318 Kingdom Documents (ADRs, docs, runbooks, Go/Rust source, skills, protocols)
    │
    ▼
Claude Haiku (via Anthropic API, ~$1.75 total)
    │ Reads each document, generates 8-25 QA pairs grounded in content
    ▼
distilled_qa_haiku.jsonl (~3-4K pairs)
    │
    ▼
Merge with existing raft_dataset_combined.jsonl (3,965 pairs)
    │
    ▼
raft_dataset_v4.jsonl (~7-8K pairs)
    │
    ▼
Zhenai Forge (Rust, cosine LR, 3 epochs)
    │
    ▼
kingdom-v4.zlora → GGUF → llama-server --lora
```

### Script

## Why Not MCP for Generation?

MCP is for Claude Code tool use (corpus_search, file_read). The distillation
script calls the Anthropic API directly because:
1. Batch processing 318 documents needs programmatic control
2. MCP adds latency per tool call — API is faster for bulk
3. The script reads files directly (no need for MCP sandboxing)
4. MCP server (zhen_mcp_server.py) is for interactive use, not batch

## Consequences

### Positive
- Expert-quality answers grounded in actual codebase (not hallucinated)
- 2x training data (7-8K vs 3,965 pairs)
- Cost negligible (~$1.75 with Haiku)
- Checkpoint/resume — can stop and restart safely
- Answers will reference real port numbers, file paths, function names

### Negative
- Requires Anthropic API key (internet access for generation)
- Generated answers reflect Claude's understanding, not Stevie's
- Training data quality capped by Haiku's capability (Sonnet would be better but 10x cost)
- One-time batch job — needs re-running when docs change significantly

### Mitigations
- Spot-check QA quality before training (D5 verification step)
- Sonnet pass on most critical documents (ADRs, CLAUDE.md)
- Re-run script periodically as codebase evolves (checkpoint makes it cheap)
