## Additional Fixes

### Fix 1: busboy-client Publish compile error
**File:** `pkg/busboy-client/client.go:343`
**Bug:** `Publish()` method returns `error` but had `return nil, fmt.Errorf(...)` (two return values)
**Fix:** Changed to `return fmt.Errorf(...)`

### Fix 2: gRPC graceful shutdown
**File:** `services/busboy/cmd/busboy/main.go`
**Bug:** `grpcServer` was created inside a goroutine, inaccessible for shutdown. Active TopicStream connections were never drained.
**Fix:** Moved `grpc.NewServer()` + service registration outside goroutine. Added `grpcServer.GracefulStop()` to shutdown sequence before HTTP shutdown.

### Fix 3: Timeguru API alignment
**File:** `services/timeguru/main.go`
**Bug:** Used non-existent API (`busboy.Connect()`, `.Subscribe(topic, callback)`, `.Shutdown(ctx)`). Was a skeleton from early development that never compiled against the real client.
**Fix:** Rewired to `busboyClient.NewClient()` + `StreamMessages()` channel receive pattern. Removed dead `pkg/telemetry` import. Replaced `ioutil.ReadFile` with `os.ReadFile`.

### Fix 4: MultiplexedLogReader data race
**File:** `pkg/runtime/logs.go`
**Bug:** `MultiplexedLogReader.Read()` had no synchronization. Concurrent goroutines in `TestMultiplexedLogReader_ConcurrentRead` raced on `buffer`, `pos`, `current`, and `readers` map.
**Fix:** Added `sync.Mutex` to struct. Converted recursive `m.Read(p)` call (which would deadlock with mutex) to iterative loop in `readLocked()`.
