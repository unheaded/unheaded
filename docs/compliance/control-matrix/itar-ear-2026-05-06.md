# ITAR / EAR Export-Control Attestation Matrix

**Date:** 2026-05-06
**Author:** Marshal post-shift extension (NORTH-STAR Appendix A Phase E14)
**Reference:** International Traffic in Arms Regulations (ITAR — 22 CFR Parts 120-130) + Export Administration Regulations (EAR — 15 CFR Parts 730-774)
**Status legend:** **MAPPED** = full coverage with evidence | **PARTIAL** = some coverage, gap noted | **GAP** = no kingdom work yet | **N/A** = not applicable | **DEFERRED** = planned, not shipped | **UNVERIFIED** = MoatGhost confirm | **REQUIRES-LEGAL** = decision needs Barrister + export-control counsel

**Critical context:** `cmd/tools/zhen-on-prem/README.md` claims ITAR reach: *"Compliance reach (per the round-table's MoatGhost analysis): FedRAMP Mod, ITAR, HIPAA, GDPR Art. 32 — once the air-gap egress proof completes."* The "once the air-gap egress proof completes" caveat is load-bearing: **the ITAR claim is aspirational, not earned today.** This matrix maps what would actually be required.

**Kingdom posture:** Unheaded uses NIST-standardized cryptography (TLS 1.3, ML-DSA-65 / FIPS 204, SLH-DSA / FIPS 205). Crypto is technically subject to **EAR Category 5 Part 2** export controls. Open-source publication may be eligible for **License Exception TSU (Technology and Software Unrestricted)** under EAR §740.13(e) for publicly-available encryption source code — but this requires a one-time notification to BIS + NSA. **Status today: not filed.**

ITAR is much narrower — defense articles + technical data. The kingdom's eBPF tracing, Wotan, etc. are not defense articles; they are dual-use commercial. ITAR scoping likely **N/A by design** *unless* an adopter customizes for a defense application (e.g. military command-and-control), at which point the *adopter* may have ITAR obligations and Unheaded may need a BAA-equivalent.

### License Exception TSU (Technology and Software Unrestricted) — §740.13

| Sub-exception | Applicability | Status |
|---------------|---------------|--------|
| TSU §740.13(d) | Operation technology and software | UNVERIFIED |
| TSU §740.13(e) | **Publicly-available encryption source code** (with one-time BIS + NSA notification) | **GAP — notification not filed** |

Per BIS guidance, **publishing encryption source code on GitHub for public download triggers §740.13(e)** if the source code is or contains 5D002-controlled software. Unheaded's GPL-3.0 publication is technically subject to this. **The notification email must be sent to BIS (`crypt@bis.doc.gov`) and NSA prior to or concurrent with first public release of the code.**

## Headline gaps for ITAR/EAR posture

1. **§740.13(e) TSU notification (one-time email to BIS + NSA)** — single 5-line email; opens TSU exception for publicly-available encryption source code.
2. **Public-facing export-restriction notice** — single page on the project README and download URLs: "Not for export to comprehensive-embargo countries (Cuba, Iran, North Korea, Syria, certain Ukraine regions) or SDN List parties."
3. **Internal screening procedure** for adopter-paid services (when funding lands) — OFAC SDN check + MEU due diligence.
4. **REQUIRES-LEGAL: BIS classification request** if any single-customer arrangement materializes for the kingdom — ECCN classification confirmation from BIS via Form BIS-748P.
5. **Cross-claim cleanup for Zhen On-Prem README** — the "ITAR reach" claim should be qualified as "EAR-controlled (5D002) with TSU notification filed; not USML / not ITAR-controlled by default" once the notification is filed.

## What is NOT a gap

- The cryptography itself (TLS 1.3, ML-DSA-65 NIST PQC, SLH-DSA NIST PQC, cloudflare/circl) is publicly-available, NIST-standardized — not a "controlled cryptographic technology" in the sense of restricted military encryption. The control surface is procedural (notifications, screening) not algorithmic.

## Adopter framing

For a DoD or defense-contractor adopter:

- **Unheaded itself remains EAR (commercial dual-use), not ITAR.**
- **The adopter's specific defense customization** (if any) is what triggers ITAR.
- **Sealed Cask + Mímir + Anamnesis Lite** can support an adopter's ITAR posture (audit, drift detection, integrity) but are not themselves ITAR articles.

This matters because misclassifying Unheaded as ITAR by mistake would prevent open-source publication entirely — a community-first doctrine violation. The honest classification is **EAR-controlled with TSU eligibility**.
