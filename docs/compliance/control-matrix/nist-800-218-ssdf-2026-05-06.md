# NIST SP 800-218 SSDF v1.1 Coverage Matrix

**Date:** 2026-05-06
**Author:** Marshal post-shift extension (NORTH-STAR Appendix A Phase E10)
**Reference:** NIST SP 800-218 v1.1 (February 2022) — Secure Software Development Framework + EO 14028 self-attestation context (CISA SSDF self-attestation form, June 2023)
**Approach:** SSDF is **the federal supply-chain attestation substrate**. Software providers selling to the U.S. federal government must self-attest to SSDF compliance. The kingdom's claim of "free to use" doesn't exempt it from SSDF if any federal agency consumes it. This matrix covers all 4 SSDF practice groups + tasks.
**Status legend:** **MAPPED** = full coverage with evidence | **PARTIAL** = some coverage, gap noted | **GAP** = no kingdom work yet | **N/A** = not applicable | **DEFERRED** = planned, not shipped | **UNVERIFIED** = MoatGhost confirm

**Kingdom posture:** SSDF is engineering-heavy — exactly the kingdom's strength. Roughly **65-75% of SSDF practices are MAPPED or PARTIAL**, with the remaining gaps being process documentation (PO group) rather than engineering (PS/PW/RV groups).

## EO 14028 self-attestation specifics

The CISA SSDF self-attestation form (June 2023) requires attestation to specific subsets of SSDF practices. Critical tasks for self-attestation include:

| Section | Practice | Kingdom Status |
|---------|----------|-----------------|
| 1 — Software Development Environment | PO.5.1 + PO.5.2 + PS.1.1 | PARTIAL |
| 2 — Trusted Source Code Supply Chains | PO.1.3 + PO.3.2 + PW.4.1 + PW.4.4 + PS.3.2 | PARTIAL → MAPPED |
| 3 — Software Provenance | PS.3.2 (SBOM) | MAPPED |
| 4 — Vulnerability Disclosure & Response | RV.1.3 + RV.2.1 + RV.2.2 | **GAP — security.txt + VDP missing** |

**The single highest-leverage item to make the kingdom EO 14028 self-attestable: a published Vulnerability Disclosure Program (VDP).** A `security.txt` (per RFC 9116) at `https://unheaded.org/.well-known/security.txt` plus a one-page VDP doc closes RV.1.3, opens self-attestation Section 4, and pairs with SOC 2 CC2.3 + GDPR Art. 33 + tonight's universal IR-plan gap.
