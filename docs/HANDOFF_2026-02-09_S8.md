## Session 8 — The Kernel Stirs

### eBPF Loading Breakthrough (E1 RESOLVED)

**Problem:** aya-ebpf 0.1.x emits a legacy `maps` ELF section. libbpf v1.7 (used by bpftool) rejects this format, requiring BTF `.maps` section. No aya-ebpf upgrade exists.

**Solution:** Created `cmd/ebpf-loader/` — a Rust binary using the `aya` crate v0.13.1, which handles legacy maps natively.

**Location:** `cmd/ebpf-loader/` (Cargo.toml + src/main.rs, 309 lines)

**Dependencies:**
```toml
aya = "0.13"
anyhow = "1"
clap = { version = "4", features = ["derive"] }
log = "0.4"
env_logger = "0.11"
ctrlc = "3"
```

**Programs loaded:**

| Program | ELF Section | Type | Attach Points |
|---------|------------|------|---------------|
| packet-marker | `xdp` | XDP | Configurable interface (default: eth0) |
| flow-tracker | `tc` | SchedClassifier | TC Ingress + TC Egress (clsact qdisc) |
| latency-probe | `kprobe`/`kretprobe` | KProbe | tcp_sendmsg (enter/exit), tcp_recvmsg (enter/exit), tcp_v4_connect (enter/exit) — 6 probes total |
| syscall-tracer | `raw_tp` | RawTracePoint | sys_enter, sys_exit |

**Usage:**
```bash
# Build
cd cmd/ebpf-loader && cargo build --release

# Dry run (validate ELF objects)
cargo run -- --dry-run --obj-dir ../../ebpf/target/bpfel-unknown-none/release

# Load all programs on loopback
sudo cargo run -- --interface lo --obj-dir ../../ebpf/target/bpfel-unknown-none/release

# Load specific programs only
sudo cargo run -- --only packet-marker,flow-tracker --interface eth0

# Pin maps for trace-collector access
sudo cargo run -- --pin-maps --interface lo --obj-dir ...
```

**Lifecycle:** Programs stay attached as long as the loader process runs. Ctrl+C or `kill` detaches all programs. BPF links auto-detach when the process exits.

### BPF Verifier Battle (packet-marker)

**Problem:** The BPF verifier requires explicit `data_end` bounds checks before every packet memory access. LLVM's optimizer eliminates these checks when it can prove they're redundant (e.g., `offset < options_end <= data_end` implies `offset < data_end`).

**6 iterations attempted:**

| # | Strategy | Result |
|---|----------|--------|
| 1 | Swap check order + `read_volatile` | Same bytecode — LLVM still eliminates |
| 2 | `black_box(data_end)` per-check | Works! But verifier hits 1M instruction limit (16,815 states) |
| 3 | Single `black_box(data_end)` at entry | LLVM re-derives through branch constraints |
| 4 | `black_box(options_end)` after data_end check | Partial — first byte read works, but `opt_len >= 18` + `offset + opt_len <= data_end` proves `offset + 18 <= data_end` |
| 5 | Remove `opt_len >= 18` check | LLVM derives from CALLER context (`tcp_hdr_len > 20`) |
| 6 | Disable option parsing entirely | **4/4 loaded** |

**Root cause insight:** `core::hint::black_box()` prevents LLVM from proving `options_end <= data_end`, but LLVM can still derive relationships through:
- Caller context (inlined function arguments carry known constraints)
- Combining `opt_len >= N` with `offset + opt_len <= data_end` to prove `offset + N <= data_end`

**Current state:** TCP/IP option trace ID extraction is disabled in `packet_marker`. The `extract_tcp_trace_id()` and `extract_ip_trace_id()` functions still exist but are unused. Core packet flow tracking (5-tuple extraction, flow state, ring buffer events) works fully.

**Fix path:** Re-enable when aya-ebpf supports BPF subprograms (`#[inline(never)]` → separate verifier contexts) or when BTF map support lands.
