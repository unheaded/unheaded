## 2. Findings

### Pi-hole

**F-P1: Pi-hole components out of date, affected by published advisories (CLEAN for IOCs, exposure finding)**
- Command: `pihole -v`
  ```
  Core version is v6.4.1 (Latest: v6.5)
  Web version is v6.5 (Latest: v6.6.1)
  FTL version is v6.6 (Latest: v6.8)
  ```
- Advisories that apply to these versions (github.com/pi-hole/{FTL,web,pi-hole}/security/advisories):
  - FTL GHSA-7997-2868-rjfg: stack overflow in answer building. Unauthenticated, adjacent network, DNS DoS. Affects ≥5.9, fixed in 6.7.1.
  - FTL GHSA-8fc6-q9x4-892v: CHAOS/TXT queries overflow a stats buffer, causing DNS DoS. Unauthenticated, fixed in 6.8. The advisory notes that with `listeningMode=ALL` (set here) any network that reaches :53 can trigger it, and west DNATs LAN :53 to the container.
  - FTL GHSA-322h-f873-hp54: cross-site/DNS-rebinding API access via a LAN browser, ≤6.7.1. **Mitigated here because a web password is set** (only password guessing at 3/s remains).
  - Local pihole→root LPEs: CVE-2026-41489 / GHSA-6w8x (Core <6.4.2, FTL <6.6.1), CVE-2026-50130 / GHSA-h8w9 (Core ≤6.4.2), plus GHSA-cf36, -xch2, -j8vh, -mff6 (published 2026-10-17). All require code execution as `pihole` first. The FTL process has ambient CAP_CHOWN (`CapAmb: 0000000002807401`), the precondition for GHSA-j8vh.
  - Web stored XSS / HTML injection (GHSA-rmr4, -3vhj, -qfpp, 2026-10-17; earlier GHSA-9rfm, -7xqw), all authenticated or admin-input.
- Exploitation traces checked (P21): none found.

## 4. Recommendations (for Stevie; nothing was applied)
