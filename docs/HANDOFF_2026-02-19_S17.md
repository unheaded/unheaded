## Architecture — What You Need to Know

### The Compute Loop (one packet, one instruction)

```
IPv6 packet with Hop-by-Hop Option (20-byte Monad: R0-R4)
        ↓ XDP hook at each namespace veth
monad-cpu-ebpf BPF program
        ↓
1. Extract flow_label (20 bits) → lookup cpu_map
2. Check stalled/halted/sleeping → skip if yes
3. FETCH: rom_map[cpu.pc] → 32-bit MBC instruction
4. DECODE: [opcode:8][dst:4][src:4][imm16:16]
5. EXECUTE: ALU / branch / memory / SYSCALL
6. Memory: l1_cache BPF LRU map (cache miss → Anamnesis event → Wotan restages)
7. Emit ComputeHopEvent via BPF ring buffer → Anamnesis
8. Return XDP_PASS → packet to next namespace
        ↓
Packet circulates 6 namespaces = 6 instructions/lap
```

### The Memory Hierarchy

```
L0: Monad (R0-R4, 20 bytes, wire speed)
L1: l1_cache BPF LRU hash (4096 × 64B = 256KB, ~100-200ns)
L2: Wotan ring buffer per flow (up to 512MB, ~1-10µs)
L3: Wotan WAL (disk, optional persistence)
```

### Cache Miss Protocol

```
BPF: cache miss → stalled=1 → emit EVENT_CACHE_MISS (flow_label + addr)
Wotan: receive CACHE_MISS → read L2 ring buffer → stage page to l1_cache BPF map
       prefetch 4 adjacent pages (spatial locality)
BPF: next packet circulation → cache hit → continue
```

### SYSCALL Bridge

```
BPF SYSCALL 0x01 → EVENT_SCREEN_WRITE → Wotan reads 64K framebuffer from L2 → WebSocket → dashboard canvas
BPF SYSCALL 0x02 → read kbd_map[0] (Wotan populates from dashboard keydown events)
BPF SYSCALL 0x03 → r0 = bpf_ktime_get_ns() / 1_000_000 (milliseconds)
BPF SYSCALL 0x04 → cpu.sleep_until = now + (r0 * 1_000_000) (busy sleep via skip)
BPF SYSCALL 0xFF → cpu.halted = 1, emit EVENT_COMPUTE_HALT
```

### BPF Maps

```rust
cpu_map:   BPF_MAP_TYPE_HASH      key=u32(flow_label)  val=CpuState      max=256
rom_map:   BPF_MAP_TYPE_ARRAY     key=u32(index)       val=u32(insn)     max=1_048_576
l1_cache:  BPF_MAP_TYPE_LRU_HASH  key=u32(addr>>6)     val=[u8;64]       max=4_096
kbd_map:   BPF_MAP_TYPE_ARRAY     key=u32(0)           val=KeyboardState  max=1
```

## Translator Known Limitations

When cross-compiling C (D-018), GCC flags are required:
```bash
-ffixed-x16 -ffixed-x17 -ffixed-x18 -ffixed-x19 \
-ffixed-x20 -ffixed-x21 -ffixed-x22 -ffixed-x23 \
-ffixed-x24 -ffixed-x25 -ffixed-x26 -ffixed-x27 \
-ffixed-x28 -ffixed-x29 -ffixed-x30 -ffixed-x31
```

Known limitations in translator.rs:
- Register-based shifts (SLL/SRL/SRA): unsupported (use `-O2` for immediate shifts)
- General JALR: only `JALR x0, 0(x1)` (return) supported
- MULH/MULHSU/MULHU: upper-half multiply not supported
- Signed loads (LH/LB): zero-extend only, no sign extension
- x16–x31: hard error (hence the `-ffixed-` flags)

## wotan-ctl Usage

```bash
# Load MBC program into BPF rom_map, initialize CPU state
go run ./cmd/wotan-ctl load-rom \
  --flow-label 0x0A3F7E \
  --file demos/mbc/gradient.mbc \
  --stats --disasm

# Load binary data into Wotan L2 ring buffer (e.g., doom1.wad)
go run ./cmd/wotan-ctl load-mem \
  --flow-label 0x0A3F7E \
  --base-addr 0x100000 \
  --file doom1.wad \
  --warm --verify

# Reset CPU state (restart program from PC=0)
go run ./cmd/wotan-ctl load-rom \
  --flow-label 0x0A3F7E \
  --file demos/mbc/gradient.mbc \
  --reset
```
