# S-QUANTUM-ARMOR BATTLE PLAN: 15 Phases, 277 Steps

**Date**: 2026-10-23
**Sprint**: S-QUANTUM-ARMOR: hybrid ML-KEM key exchange on every TLS/SSH link we own, a checked-in crypto inventory (CBOM), a gate that fails on classical-only pinning, and signed evidence (`yggdrasil-evidence` + Heimdall signed drift events).
**Size**: Medium-Large (Warmonger scale: Large by step count; 6 parallel tracks keep wall-clock at Medium-Large)
**Prerequisite**: develop at or after `443de3f82`; S17 batch merged (unsigned commits are fine, see VARIABLES `qa_commit`); Go toolchain go1.27.3 (go.mod pin); `cargo` stable; `docker` usable via `sudo` (throwaway containers only); read-only `ssh govan@east` works.
**Target**: Every first-party TLS endpoint negotiates a hybrid ML-KEM group (proven by handshake tests that fail on a classical group), no repo config can silently pin classical-only key exchange (a meta-gate-registered lint fails on it), `compliance/crypto/cbom.cdx.json` is regenerated by a script and a gate fails when it is stale, and `yggdrasil-evidence` plus Heimdall produce and verify ML-DSA-65 signed evidence. Host changes (Well PG upgrade, sshd, WireGuard) are prepared, proven in throwaway containers or dry runs, and left as [ESCALATE] steps for Stevie.
**Estimated Duration**: 16-22 hours across 3-4 sessions (critical path ~10 h)
**Agent Strategy**: Phases 0-4 sequential (Coordinator). Then 6 tracks: KEX-Go (5→6), KEX-Rust (7), Well (8), Hosts (9), Evidence (10→11), Signed drift (12). Tracks may run as parallel agents in their own git worktrees; Phase 13-14 sequential after all tracks merge.
**Commit Cadence**: Every 5 steps (calculated: max(3, min(5, 277/20)) = 5), plus red→green and every new file; each phase's last [C] lands just before its exit gate, which only verifies (record the gate output in the next commit body). Phases 0-1 change no tracked file, so their [C] steps are explicit no-ops. Tolerance: a gap may stretch to 5+3 steps where the steps in between are reads, decisions or verifications.
**Stuck Protocol**: Skip after 3x the step's time estimate or 2 failed debug attempts; write a `[STUCK]` marker, commit, continue with the next independent step (Skip Protocol, Warmonger).
**Never**: `git push`; promote to staging; touch Monad v0x01 wire format; change a host (west/east) outside an `[ESCALATE]` step Stevie approved; print or commit a key, PSK or password.

## APPENDIX A: EMERGENCY PROCEDURES

**A.1 aws-lc-sys does not build** (Phase 7). 1) `cargo build -vv 2>&1 | grep -iE 'cmake|nasm|cc|error' | head`. 2) Missing C compiler or cmake on west or the CI image is a tool install: [ESCALATE] (host change). 3) Mark the WAF/zhend steps [STUCK], keep their lint lines in the baseline with `# STUCK: aws-lc build`, continue with 7.3. 4) Never fall back to the ring provider.

**A.2 A Strict TLS endpoint breaks a real client** (after Phase 5). 1) Identify the client and its TLS stack (`openssl s_client`-style probe with that client's groups). 2) Move ONLY that site to Preferred (`ApplyPreferred`), with a test documenting the client, and record it `hybrid-opportunistic` in the CBOM. 3) Never re-pin `CurvePreferences` to classical: the lint will fail and the meta-gate proves it.

**A.3 The meta-gate refuses a dirty tree or fails to restore**. 1) Always run it in `$SCRATCH/mg` (a clean clone), never in the working tree. 2) If it was run in the tree by mistake: `git status --porcelain`; restore only files the meta-gate touched (`git checkout -- <file>`, `rm` its untracked `zz_meta_gate_*` probes); never `git stash` (shared stash stack) and never `git clean -fdx`.

**A.4 Throwaway containers or ports left behind** (Phases 0, 8). `sudo docker ps -a --filter name=qa- --format '{{.Names}}' | xargs -r sudo docker rm -f`; ports were bound to 127.0.0.1 only, so nothing was exposed. Never touch containers without the `qa-` prefix (the live stack's names).

**A.5 A handshake test hangs or flakes**. `net.Pipe` is synchronous: both handshakes must run concurrently and the pqtest deadline must be set. Run with `-count=20 -race`; a flake is a bug in the helper, not something to retry around.

**A.6 The CBOM is not deterministic**. Diff two runs (`cmp` then `jq -S . | diff`); usual causes are map iteration order, absolute paths (use repo-relative), timestamps, or reading `git ls-files` from a different worktree. Fix the generator; never commit a CBOM that changes on regeneration without a tree change.

**A.7 gpg-agent timeout while committing**. `qa_commit` already falls back to `--no-gpg-sign` (memory: unsigned when AFK). Note it in next.md; `scripts/resign-unpushed.py` after Stevie caches the key.

**A.8 A key, seed, PSK or password reached a terminal log, file or commit**. 1) STOP. 2) If only in `$SCRATCH`: shred and delete it. 3) If in a commit (even unpushed): do not push; [ESCALATE] to Stevie with the commit hash (history rewrite and rotation are his calls; CLAUDE.md "a credential in the tree is a credential in git history"). 4) WireGuard PSK exposed → that PSK is burned; rotation (E3) becomes urgent.

**A.9 Proto regeneration produces different generator versions**. Read `services/wotan/proto/generate.sh` for the pinned `protoc`/plugin versions; install those into `$SCRATCH/bin` and put it first on `PATH`; regenerate; the `.pb.go` header must show the same versions as before. If the pinned `protoc` can't be fetched: [STUCK] the proto step; Phase 12 can still land scoped prefixes without `signed_at` on events (subscriber verification then waits).

**A.10 Wotan refuses Heimdall's signed drift in a lab run**. Expected until E5: `drift.` ships with no trusted keys (fail closed). For the e2e test the key is injected in-process; never add a key to `configs/wotan.yaml` from this sprint.

**A.11 SSH lockout after E2 (only if Stevie executed it)**. Recovery needs console or the still-open second session the E2 procedure requires; restore `/etc/ssh/sshd_config.d/00-unheaded.conf` from its `.bak` and `systemctl reload ssh`. This plan never performs E2 itself.
