# Unheaded Telemetry Stack

Rewritten 2026-10-27 against `monitoring/docker-compose.yml`, the root
`docker-compose.yml` and `docker/telemetry/`. The earlier version described a
vLLM exporter, an `ebpf-exporter` on 9435 and a VictoriaMetrics topology that are
not what runs; it is in git history.

## 1. What runs where (west)

```
root docker-compose.yml (kingdom stack)
├── victoria (VictoriaMetrics v1.108.1)  :8428   30-day retention, scrapes /etc/victoria/scrape.yml
├── clickhouse (24.12)                   127.0.0.1:8123 / 127.0.0.1:9000   log store (unheaded_logs.logs)
└── vector                                journald → ClickHouse; log-volume and auth-failure SLIs
                                          as Prometheus metrics (config/vector/vector.yaml)

monitoring/docker-compose.yml (monitoring stack, network "monitoring")
├── prometheus (v3.15.0)       :9090    rules monitoring/prometheus/rules/*.yml, 30-day TSDB,
│                                       remote_write → VictoriaMetrics :8428
├── alertmanager (v0.34.1)     127.0.0.1:9093   config generated by `go run ./cmd/alert-policy`
├── alert-mailer               127.0.0.1:19130  the only thing that sends alert mail (ADR-100)
├── grafana (10.4.0)           :3000
├── loki (3.0.0)               :3100
└── victoriametrics (v1.108.1) no host port; 12-month retention inside the monitoring network
```

Every container runs as its own uid from `pkg/uids` (Prometheus 16700, Grafana
16701, Loki 16702, VictoriaMetrics 16703, Alertmanager 16709, alert-mailer 16710),
read-only root, `cap_drop: [ALL]`. A `volume-init` one-shot chowns each volume.

Services expose `/metrics` themselves: HTTP metrics come from
`pkg/httputil.NewServiceMetrics` (`unheaded_http_*`), host metrics from Huginn
(`deploy/systemd/huginn.service`).

## 2. Scrape jobs

`monitoring/prometheus/prometheus.yml` (west) and `prometheus-host-b.yml` (east).
West jobs: `prometheus`, `node_exporter`, `unheaded-daemon`, `huginn`,
`frr_exporter`, `bird_exporter`, `routing_health`, `doom_services`, `kev-poller`,
`vector`, `dashboard-backend`, `wotan`. Check the file for targets; it is the
source of truth.

## 3. Alerting

Only SLO/SLA deviation pages (ADR-100). One policy file,
`observability/alerting/policy.yaml`, generates
`monitoring/prometheus/rules/slo.yml` and `monitoring/alertmanager/alertmanager.yml`
(`go run ./cmd/alert-policy`; CI fails when they are stale). Alertmanager hands
pages and tickets to alert-mailer by webhook; alert-mailer caps mail at 6 a day and
sends a 09:00 digest. Mode is `send` since 2026-10-27. Details: `wiki/Alerting.md`.

## 4. Starting it

`docker compose -f monitoring/docker-compose.yml up -d` (needs `sudo` on west).
Until FND-024 is closed, `scripts/kingdom-startup.sh` starts only the root compose
file, so the monitoring stack is not started at boot and `pkg/sloguard` fails
closed without `slo:error_ratio:5m`.

## 5. docker/telemetry

`docker/telemetry/docker-compose.telemetry.yml` is an older standalone stack
(Prometheus 2.51, VictoriaMetrics 1.99, Loki 2.9 + Promtail, node-exporter,
Grafana). Nothing starts it on west or east; the Kubernetes build plan maps it to
`telemetry/*` manifests. Prefer `monitoring/` for anything live.
