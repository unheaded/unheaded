# Unheaded Telemetry Stack

Rewritten 2026-10-27 against `monitoring/docker-compose.yml` and the root
`docker-compose.yml`. Updated 2026-11-11 for ADR-117: one Grafana, one metrics
store, one log store. Earlier versions are in git history.

## 1. What runs where (west)

```
root docker-compose.yml (kingdom stack)
├── victoria (VictoriaMetrics v1.155.0)  :8428   the only metrics store; 30-day retention;
│                                                scrapes config/victoria/scrape.yml (both hosts)
├── grafana (11.5.1)                     :3001   the only Grafana; dashboards provisioned from
│                                                config/grafana/provisioning/dashboards/kingdom/
├── clickhouse (24.12)                   127.0.0.1:8123 / 127.0.0.1:9000   log store (unheaded_logs.logs)
└── vector                                journald → ClickHouse; log-volume and auth-failure SLIs
                                          as Prometheus metrics (config/vector/vector.yaml)

monitoring/docker-compose.yml (the alert path, network "monitoring")
├── prometheus (v3.15.1)       127.0.0.1:9090   rule evaluator only: monitoring/prometheus/rules/*.yml;
│                                               remote_write of rule results → VictoriaMetrics :8428
├── alertmanager (v0.34.1)     127.0.0.1:9093   config generated by `go run ./cmd/alert-policy`
└── alert-mailer               127.0.0.1:19130  the only thing that sends alert mail (ADR-100)
```

Retired 2026-11-11 (ADR-117): the monitoring stack's Grafana 10.4 (3000), Loki
(3100, no shipper, no streams) and its second VictoriaMetrics (never written
to). What they held and why nothing was lost:
`docs/sweeps/ONE-GRAFANA-INVENTORY-2026-11-11.md`. Moving a host that still
runs them: `docs/runbooks/one-grafana-cutover.md`.

Every container runs as its own uid from `pkg/uids` (Prometheus 16700, Grafana
16701, VictoriaMetrics 16703, Alertmanager 16709, alert-mailer 16710),
read-only root, `cap_drop: [ALL]`. A `volume-init` one-shot chowns each volume.

Services expose `/metrics` themselves: HTTP metrics come from
`pkg/httputil.NewServiceMetrics` (`unheaded_http_*`), host metrics from Huginn
(`deploy/systemd/huginn.service`).

## 2. Scrape jobs

`config/victoria/scrape.yml` is what fills the store: the compose services, and
over the overlay the host units on west and east (node_exporter, huginn,
trace-collector, kev-poller, heimdall, vector, syslog-relay, zhen-agentd, the
second host's daemon and dashboard backend). VictoriaMetrics reaches the
overlay through the compose network `scrape` (IPv6) and `-enableTCP6`.

`monitoring/prometheus/prometheus.yml` keeps scraping what its rules read, and
forwards only recording-rule series, `ALERTS`, `ALERTS_FOR_STATE` and its own
two jobs (`alert-mailer`, `prometheus`) to the store. A target in both files is
scraped twice and stored once. Check the files for targets; they are the source
of truth.

## 3. Alerting

Only SLO/SLA deviation pages (ADR-100). One policy file,
`observability/alerting/policy.yaml`, generates
`monitoring/prometheus/rules/slo.yml` and `monitoring/alertmanager/alertmanager.yml`
(`go run ./cmd/alert-policy`; CI fails when they are stale). Alertmanager hands
pages and tickets to alert-mailer by webhook; alert-mailer caps mail at 6 a day and
sends a 09:00 digest. Whether it sends or only records is `mailer.mode` in the
policy file. Details: `wiki/Alerting.md`.

Prometheus retires when its rules have another evaluator (ADR-116, ADR-117
question of 2026-11-11). Until then it is the one remaining duplicate.

## 4. Starting it

`docker compose -f monitoring/docker-compose.yml up -d` (needs `sudo` on west).
`scripts/kingdom-startup.sh` starts it before the root compose file (FND-024):
without `slo:error_ratio:5m`, `pkg/sloguard` fails closed.
